# medcvr-il

## Setup

```bash
git submodule update --init --recursive
sudo apt install ros-humble-control-msgs
```

## Install Dependencies

Use `uv` (recommended). Python must be 3.10 for ROS2 Humble, and 3.12 for ROS2 Jazzy. Update Python version in pyproject.toml depending on ROS2 version if needed.

If this repo is inside a ROS workspace (for example `~/nirmal/il_ws/src/medcvr-il`), install dependencies from the workspace root:

```bash
cd ~/nirmal/il_ws

# ROS dependencies
source /opt/ros/humble/setup.bash
rosdep update
rosdep install --from-paths src --ignore-src -r -y

# Python dependencies (uv virtual environment)
cd src/medcvr-il
uv sync --frozen

# LeRobot (editable install — brings in draccus, diffusers, etc.)
uv pip install -e .
uv pip install --python .venv/bin/python -e ./lerobot
```

If you are working directly from this repo (not a larger workspace):

```bash
source /opt/ros/humble/setup.bash
uv sync --frozen
uv pip install -e .
uv pip install --python .venv/bin/python -e ./lerobot
```

## Data Conversion

### Example command
```bash
uv run python scripts/data_conversion.py \
    --config config/dvrk_cut_mesh_multi_rgb_dp.yaml \
    --raw_dir data/mesh_cut \
    --out_dir data/mesh_cut_lerobot_v4 \
    --image-type mp4 \
    --state zero \
    --relative_action \
    --robot_env Unity \
    --jaw joint \
    --jaw_file jaw_state.txt \
    --repo_id Ameyapores/mesh_cut_dataset_v4 \
    --cameras 0,2 \
    --fps 15 \
    --push
```

### Configuration
Use `--config` to specify a YAML file.

- YAML values load first.
- CLI overrides only `data_conversion` fields.
- `topics` and image preprocessing are taken from YAML.

The converter reads:

- `topics`
- `global_image_pre_processor`
- `data_conversion.*`

Image preprocessing:

- Camera/topic metadata: maps each key to ROS topic name and message type.
- Image preprocessing overrides: `topics.<key>.pre_processor` can set per-camera crop/resize/alignment.
- Fallback behavior: if a camera has no `pre_processor`, `global_image_pre_processor` is used.

Important `data_conversion` fields:

- `raw_dir`: Path to recorded episodes (input root).
- `out_dir`: Destination path for the generated LeRobot dataset (recreated on run).
- `image_type`: Image loading mode for camera streams (`png`, `jpg`, `mp4`).
- `fps`: Output frame rate used for video-backed dataset media.
- `state`: Observation state representation mode (for example `zero`, `xyz`, `xyz_quat`, `xyz_6d`, and jaw variants).
- `action`: Action representation mode (for example `xyz`, `xyz_quat`, `xyz_6d`, and jaw variants).
- `relative_action`: If true, actions are converted to relative deltas between timesteps.
- `robot_env`: Input data convention (`Unity` or `franka`) to select pose parsing behavior.
- `jaw`: Jaw/gripper data mode (`none`, `joy`, `joint`, `joint_state`).
- `jaw_file`: Jaw data filename inside each episode folder.
- `eef_file`: End-effector pose filename inside each episode folder.
- `cameras`: Optional comma-separated camera indices to include (for example `0,2`).
- `cam_names`: Optional comma-separated camera folder names to use explicitly.
- `repo_id`: Dataset repository id used when pushing to hub.
- `push`: If true, push the converted dataset to the hub after conversion.
- `task`: Task label written into dataset metadata.
- `transform_matrix`: Optional 4x4 transform applied to EEF pose before state/action construction.

### Expected input layout
```text
raw_dir/
    episode_000/
        cam0/
        cam1/
        ...
        eef_position.txt
        jaw_state.txt
        timestamp.txt
    episode_001/
    ...
```
